# Fictional software-change provider PRD (supplemental)

This change-scoped document is supplemental/non-authoritative and supplements [authoritative product PRD](docs/PRD.md); it is not an alternate product authority. It describes the provider slice used by the reference workflow and must be read with the authoritative PRD and requirement proof.

Provider validates authored artifact structure and declared revision links before aggregating supplied external review evidence for a selected checked transition. The generic schema checker and versioned profiles consume one bounded schema contract: object, array, and string types; exact object, array, and string keyword sets; literal-false additionalProperties; rejection of unknown or misplaced keywords; and exhaustive deterministic path/rule violations. Full JSON Schema and custom artifact dialects are outside this contract. The checked transition evaluator maps each named violation into denial details before or without evidence satisfaction. Evidence remains opaque and external: provider applies configured current-revision, config-version, supersession, and exact declared name-kind identity rules without judging semantic truth.

Canonical files `fictional-repo/provider/data/configs/minimal.json`, `fictional-repo/provider/data/configs/standard.json`, and `fictional-repo/provider/data/configs/high-rigor.json` own existing profile mappings, counts, policies, and artifact schemas; canonical templates and `fictional-repo/provider/data/reviewer-protocol.md` own exact prompt/template/protocol bytes. Design freezes only versioned-data boundary: selected run exposes these policies, schemas, prompts, templates, and protocol as inspectable reference data. Design does not choose or hard-code profile catalog. Declared profile obligations, including terminal configured validation, are used as-is; inferred obligations and mutable defaults are rejected.

The provider runs one fresh local process per request and returns allow, deny, or unsupported. It does not invoke a semantic judge, read arbitrary repository paths, write authored artifacts, route workflow state, or persist engine state. The engine owns workflow progression. Exact declared identity is unauthenticated, so a subject can claim another identity; deterministic declared-identity checks remain provider behavior, while external process and provenance controls remain outside scope.

The seven implementation packets, executable tests, and [requirement-to-proof matrix](implementation-evidence/requirement-to-proof.md) document how this bounded change is proved without presenting synthetic evidence as semantic review quality.
