# Fictional repository PRD (authoritative)

This document is authoritative for product behavior in `fictional-repo`. The repository coordinates externally performed software changes through durable workflow states. The engine owns workflow progression and state; provider evaluation is a fresh, stateless local subprocess call.

The provider exposes frozen policies and artifact schemas, validates only contained authored artifacts against one bounded schema contract, and checks declared cross-artifact revision links. The contract permits only object, array, and string types; object additionalProperties, properties, required, and type; array items, minItems, and type; and string enum, minLength, and type. additionalProperties must be false; unknown keywords and invalid placement are rejected; instance evaluation collects every applicable violation in deterministic path/rule order. Its generic schema checker emits that exhaustive result, and the checked transition evaluator maps every named violation into denial details before or without evidence satisfaction, so external evidence cannot turn malformed structure into an allow.

Canonical files `fictional-repo/provider/data/configs/minimal.json`, `fictional-repo/provider/data/configs/standard.json`, and `fictional-repo/provider/data/configs/high-rigor.json` own existing profile mappings, counts, policies, and artifact schemas; canonical templates and `fictional-repo/provider/data/reviewer-protocol.md` own exact prompt/template/protocol bytes. Design freezes only versioned-data boundary: selected run exposes these policies, schemas, prompts, templates, and protocol as inspectable reference data. Design does not choose or hard-code profile catalog. No inferred or built-in obligations or mutable defaults supplement declared profile data.

External review evidence is opaque supplied input. Provider applies configured gate, axis, current subject revision, config-version, supersession, and exact declared name-kind identity rules. Provider does not judge semantic truth, invoke a model, read arbitrary repository paths, write authored artifacts, route workflow state, or change durable engine state. The reference workflow reaches its terminal state only after configured validation obligations satisfy.

Declared name-kind identity is unauthenticated: a subject can claim another identity. Provider preserves deterministic declared-identity checks; external process and provenance controls remain outside scope, and this residual is accepted.

Requirement proof is recorded in [requirement-to-proof matrix](../implementation-evidence/requirement-to-proof.md), and `../scripts/assert-requirement-proof.py` checks its exact executable mapping against supplied repository-state inventory. [supplemental change PRD](../loop-engine-software-change-provider-prd.md) is supplemental and non-authoritative; it cannot create parallel product truth. The technical design and task packets are likewise change-scoped supporting material.
