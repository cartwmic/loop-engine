# Fictional software-change provider task packets (supplemental)

These packets support authoritative [authoritative product PRD](docs/PRD.md). They define seven worker-sized tasks with explicit dependencies, noncolliding deliverables, validation, and handoffs. [supplemental change PRD](loop-engine-software-change-provider-prd.md) is supplemental and non-authoritative.

## Dependency graph

```text
protocol-and-config-contract
├── schema-and-artifact-validation
├── evidence-evaluator
└── versioned-reference-data
schema-and-artifact-validation ──> versioned-reference-data
schema-and-artifact-validation ─┐
evidence-evaluator              ├── checked-transition-evaluator
versioned-reference-data       ─┘
checked-transition-evaluator ─┐
versioned-reference-data      ├── acceptance-proof
acceptance-proof ─────────────┘
authoritative-doc-integration depends on acceptance-proof
```

## Frozen predecessor contract

Schema-and-artifact-validation consumes exact shared schema decision `design.json#/decisions/1`. Versioned-reference-data depends on protocol-and-config-contract and schema-and-artifact-validation, then consumes existing canonical files `fictional-repo/provider/data/configs/minimal.json`, `fictional-repo/provider/data/configs/standard.json`, `fictional-repo/provider/data/configs/high-rigor.json`, `fictional-repo/provider/data/templates/intent.md`, `fictional-repo/provider/data/templates/design.md`, `fictional-repo/provider/data/templates/task-packet.md`, `fictional-repo/provider/data/templates/implementation-report.md`, `fictional-repo/provider/data/templates/validation-report.md`, and `fictional-repo/provider/data/reviewer-protocol.md`. Those canonical files own existing profile catalog and exact bytes/semantics; integration may only embed or expose them. The versioned-data element `design.json#/elements/3` freezes this inspectable boundary. No prompt, axis, or schema authoring is allowed.

The shared schema language permits only object, array, and string types; object additionalProperties/properties/required/type; array items/minItems/type; and string enum/minLength/type. additionalProperties is false, unknown or misplaced keywords are rejected, and every applicable instance violation is collected in deterministic path/rule order. This rejects full JSON Schema and custom artifact dialects.

## Packets

1. **protocol-and-config-contract** — Own `fictional-repo/provider/Cargo.toml`, `fictional-repo/provider/src/main.rs`, `fictional-repo/provider/src/protocol.rs`, `fictional-repo/provider/src/config.rs`, `fictional-repo/provider/tests/describe_protocol.rs`, and `fictional-repo/provider/tests/snapshots/describe.json`. Define strict one-request/one-result dispatch and describe output. Validate malformed requests, unknown operations and fields, and snapshot bytes. Handoff: downstream tasks consume DTOs and profile-query types without reshaping them.
2. **schema-and-artifact-validation** — Own `fictional-repo/provider/src/schema.rs`, `fictional-repo/provider/src/artifacts.rs`, `fictional-repo/provider/tests/evaluate.rs`, and `fictional-repo/provider/tests/a3.rs`. Consume shared schema decision `design.json#/decisions/1`; emit deterministic exhaustive structural violations and revision-link diagnostics. Validate absent, unparseable, mismatched, and escaping artifacts, including `evaluate.rs::schema_deny_reports_every_simultaneous_structural_violation` for checker-to-denial projection. Handoff: versioned-reference-data validates canonical data after this checker; checked-transition-evaluator consumes structural output before evidence satisfaction.
3. **evidence-evaluator** — Own `fictional-repo/provider/src/evidence.rs` and `fictional-repo/provider/tests/a5.rs`. Aggregate supplied evidence by configured identity, revision, version, supersession, and axes. Validate stale, self-authored, duplicate-author, and standing-fail mechanics. Handoff: checked-transition-evaluator consumes ordered diagnostics and satisfaction state.
4. **versioned-reference-data** — Depends on `protocol-and-config-contract` and `schema-and-artifact-validation`. Own integration of existing canonical files `fictional-repo/provider/data/configs/minimal.json`, `fictional-repo/provider/data/configs/standard.json`, `fictional-repo/provider/data/configs/high-rigor.json`, `fictional-repo/provider/data/templates/intent.md`, `fictional-repo/provider/data/templates/design.md`, `fictional-repo/provider/data/templates/task-packet.md`, `fictional-repo/provider/data/templates/implementation-report.md`, `fictional-repo/provider/data/templates/validation-report.md`, and `fictional-repo/provider/data/reviewer-protocol.md`, plus `fictional-repo/provider/src/embedded_data.rs`, `fictional-repo/provider/tests/embedded_data.rs`, and `fictional-repo/provider/tests/shipped_data.rs`. Preserve exact bytes and semantics except integration needed to embed or expose them; no prompt, axis, or schema authoring. Consume `design.json#/elements/3` and `design.json#/decisions/1`. Validate `embedded_data::embedded_manifest_exactly_matches_on_disk_data_tree`, `shipped_data::all_profiles_pass_production_config_validation_and_have_exact_subjects`, `shipped_data::profiles_carry_exact_shipped_profile_mapping_and_author_counts`, `shipped_data::every_axis_prompt_references_subject_template_schema_and_all_antipedantry_guards`, and `schema::tests::allowlist_pin_matches_normative_subset` after schema checker handoff. Handoff: checked-transition-evaluator and acceptance-proof consume validated profile projections.
5. **checked-transition-evaluator** — Own `fictional-repo/provider/src/gates.rs`, `fictional-repo/provider/src/workflow.rs`, `fictional-repo/provider/tests/a1.rs`, `fictional-repo/provider/tests/a9.rs`, and `fictional-repo/provider/tests/a15.rs`. Consume schema, evidence, and versioned-data outputs; preserve structural-denial precedence, project outcome taxonomy, and enforce terminal obligations. Handoff: acceptance-proof consumes response and workflow behavior.
6. **acceptance-proof** — Own `fictional-repo/provider/tests/a2.rs`, `fictional-repo/provider/tests/a7.rs`, `fictional-repo/provider/tests/a8.rs`, `fictional-repo/provider/tests/a11.rs`, `fictional-repo/provider/tests/a12.rs`, `fictional-repo/provider/tests/a13.rs`, `fictional-repo/provider/tests/a14.rs`, `fictional-repo/provider/tests/r25.rs`, `fictional-repo/implementation-evidence/requirement-to-proof.md`, and `fictional-repo/scripts/assert-requirement-proof.py`. Map each exact acceptance requirement to named executable proof, including `evaluate.rs::schema_deny_reports_every_simultaneous_structural_violation` and `evaluate.rs::evidence_phase_denies_with_configured_axis_diagnostics`; checker validates exact mapping against supplied repository-state proof inventory; keep supplied review records bounded to mechanics and semantic review external.
7. **authoritative-doc-integration** — Own `fictional-repo/README.md`, `fictional-repo/provider/README.md`, `fictional-repo/docs/PRD.md`, `fictional-repo/loop-engine-software-change-provider-prd.md`, `fictional-repo/loop-engine-software-change-provider-technical-design.md`, `fictional-repo/loop-engine-software-change-provider-task-packets.md`, and `fictional-repo/scripts/assert-doc-authority.py`. Link root/provider/docs/proof surfaces, make `fictional-repo/docs/PRD.md` authoritative, mark the change PRD supplemental/non-authoritative, and run `python3 fictional-repo/scripts/assert-requirement-proof.py` plus `python3 fictional-repo/scripts/assert-doc-authority.py` to check proof mapping, authority, exact acceptance coverage, and relative Markdown links. Validation report / docs-integrated review consumes final document, checker, and proof paths.

Acceptance-proof depends on checked-transition-evaluator and versioned-reference-data. Versioned-reference-data is downstream of schema-and-artifact-validation, while evidence-evaluator remains parallel with schema-and-artifact-validation. No task owns another task's mutable file; broad workspace validation may execute downstream tests after handoff.
