# Fictional software-change provider technical design (supplemental)

`fictional-repo` uses one fresh provider process per request. Frozen profile data supplies policies, bounded artifact schemas, templates, and reviewer protocol. Provider reads only contained authored artifacts; run configuration declares cross-artifact revision links. Evidence aggregation keys supplied verdicts by gate, axis, subject revision, config version, and exact declared name-kind identity.

The generic schema checker and versioned data profiles share one bounded schema language: types are object, array, or string; object keywords are exactly additionalProperties, properties, required, and type; array keywords are exactly items, minItems, and type; string keywords are exactly enum, minLength, and type. additionalProperties is literal false. Unknown keywords and invalid placement are rejected, and instance evaluation collects every applicable violation in deterministic path/rule order. Full JSON Schema and a custom artifact language are rejected. The checked transition evaluator consumes that result and maps every named violation into denial details before or without evidence satisfaction. It evaluates configured external evidence only after structural checks, then returns allow, deny, or unsupported for the selected transition. This is structural architecture, not procedure prose.

Versioned data profiles are generic selected-run reference data. Canonical files `fictional-repo/provider/data/configs/minimal.json`, `fictional-repo/provider/data/configs/standard.json`, and `fictional-repo/provider/data/configs/high-rigor.json` own existing profile mappings, counts, policies, and artifact schemas; canonical template and reviewer-protocol files own their exact bytes. Design freezes only boundary: selected run exposes these policies, schemas, prompts, templates, and protocol as inspectable reference data. Design does not hard-code or choose profile catalog. Obligations come from canonical declared profile data and terminal configured validation, not inferred or built-in rules or mutable defaults.

Provider never routes, invokes a semantic judge, writes artifacts, or changes durable engine state. The engine owns workflow progression and persistence. Exact declared name-kind identity is unauthenticated, so a subject can claim another identity. Provider preserves deterministic declared-identity checks; external process and provenance controls remain outside scope, and this residual is accepted.
