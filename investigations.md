## Supported recovery and stopping rule

1. Start with a fresh action/full `show`; identify the frozen runtime, binding, current subject/revision, capture directory, latest invocation, and exact requested input. Status/compact output is not mutation permission.
2. For a bound attempt, wait while owned work is live. Use `invocation-progress` only for targeted graph diagnosis, and inspect `summary.json`, `attempts.json`, raw stdout/stderr, sidecars, and cleanup state. A receipt or exit code is not a semantic pass.
3. On a failed implementation graph, use the narrowest honest route: exact `{plan_revision, task_roots}` for a current task-owned correction only when every unselected prerequisite has a successful same-revision standing result; use the explicit no-task repair path only for a current accepted unresolved finding with no honest task owner; revise the owning plan/design/intent when decomposition or upstream obligations are wrong. `backlog_t02_plan_graph_recovery_reuses_b_before_retry_and_reaches_current_checkpoint` proves the public selected retry and negative `force_fresh` refusal.
4. Never overlap a retry with live or cleanup-pending work, blindly rerun the full graph, relabel a historical receipt, copy a verdict under another author, or treat a weaker/new profile as recovery. If no process/sidecar/capture/target evidence is changing and owned work is gone, stop, preserve the capture, verify cleanup, and return the concrete blocker. An interrupted cancellation remains incomplete; resume the supported cancellation request rather than declaring success.

This is the minimum supported recovery rule in `docs/agent-usage.md` and the software-change skill. It preserves rich append-only history and makes missing external evidence an explicit handoff instead of manufacturing completion.
